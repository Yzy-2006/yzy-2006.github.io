## 一、核心思想

可以把 Frequency-space Action Sequence Tokenization，简称 FAST 理解成一句话：

>不要把机器人每个时刻的连续动作逐个离散化，而是先把“一整段动作轨迹”变换到频域，用少量频率成分描述整段运动，再把这些频率系数压缩成离散 token。

## 二、DCT(Discrete Cosine Transform，离散余弦变换)

概念上：

$$
a(t) \approx c_0 + c_1 \cos(\omega_1 t) + c_2 \cos(\omega_2 t) + \cdots
$$

其中：

- $c_0$：整体偏移；
- $c_1, c_2$：大尺度运动形状；
- 更高阶 $c_k$：越来越快速的变化。

>对于机器人轨迹这种较为平滑的信号，能量集中在低频，高频对应的系数很小
{: .prompt-info}

## 三、FAST 的 5 个步骤

FAST（Frequency-space Action Sequence Tokenization）的目标，是把一段连续的机器人 **action chunk** 转换成较短的离散 token 序列，使机器人动作能够像文本 token 一样交给自回归 Transformer 进行学习。假设一段动作轨迹为

$$
A\in\mathbb{R}^{H\times D}
$$

其中 $H$ 表示时间长度，$D$ 表示 action dimension。FAST 的整体流程为：

**Normalization → DCT → Quantization → Low-frequency-first Flatten → BPE**

1. **Normalization**  
   首先对每个 action dimension 分别进行归一化，将不同维度、不同机器人之间尺度差异很大的动作值映射到相近范围。FAST 通常根据训练数据中各动作维度的分位数进行归一化，而不是简单使用最大值和最小值，因此对异常值更加稳定。经过这一步后，关节角度、末端位移、夹爪动作等不同类型的连续控制量可以使用统一的后续编码方式。

2. **DCT（Discrete Cosine Transform）**  
   接着，对每个 action dimension **沿时间轴执行 DCT**，将动作轨迹从时间域转换到频率域。例如一个关节未来 $H$ 个时刻的动作
   $$
   [a_0,a_1,\dots,a_{H-1}]
   $$
   会被转换成
   $$
   [c_0,c_1,\dots,c_{H-1}]
   $$
   这些系数分别描述不同频率的运动成分。由于真实机器人动作通常比较平滑，相邻时刻的动作高度相关，因此主要信息往往集中在少数低频系数中，而高频系数通常很小。DCT 本身并不会减少数据量，而是把原本分散在很多时间点上的信息集中到低频区域，为后续压缩创造条件。

3. **Quantization**  
   DCT 得到的频率系数仍然是连续浮点数，因此 FAST 会先乘一个缩放系数 $\gamma$，再进行取整：
   $$
   Q=\operatorname{round}(\gamma C)
   $$
   例如一个很小的高频系数 `0.003` 在缩放取整后可能直接变成 `0`。由于高频部分本来就普遍接近 0，量化后频率矩阵会出现大量 0，从而变得非常稀疏。这一步是真正产生**有损压缩**的关键：一些很小、对整体轨迹影响不大的高频细节被舍弃，而主要的低频运动结构被保留下来。

4. **Low-frequency-first Flatten**  
   频率系数最初仍然是“动作维度 × 频率”的二维结构，因此需要将其展平成一维序列。FAST 并不是先展开某一个关节的全部频率，而是按照**频率优先**的顺序排列：先放所有 action dimensions 的最低频系数，再放所有维度的第二低频系数，然后依次向更高频展开。这样，自回归模型在生成 token 时会优先预测决定整个动作轨迹大致形状的低频信息，然后再逐渐补充高频细节，即：
   `整体运动趋势 → 中等尺度变化 → 局部细节`。

5. **BPE（Byte Pair Encoding）**  
   经过量化和展开后，会得到一串整数，例如：
   `12, -3, 8, 1, 0, 0, 0, 0, ...`
   由于高频区域存在大量 0，并且机器人动作中还会反复出现一些相似的整数模式，FAST 最后使用 BPE 将这些高频出现的整数片段合并成单个 token。例如反复出现的 `[0,0,0,0]` 可以被一个 token 表示，从而进一步缩短 action token sequence。与 Quantization 不同，BPE 本身主要是一种**无损的序列压缩**，它不会再次改变动作信息，而只是用更少的 token 表示重复模式。

因此，FAST 的核心思想可以概括为：

> **先利用 DCT 将平滑动作的主要信息集中到低频，再通过 Quantization 消除不重要的高频细节，最后利用 Low-frequency-first 排序和 BPE 将整个 action chunk 编码成紧凑的离散 token 序列。**

可以进一步记成：

$$
\text{Continuous Action}
\rightarrow
\text{Normalize}
\rightarrow
\text{Frequency Space}
\rightarrow
\text{Sparse Integers}
\rightarrow
\text{Flatten}
\rightarrow
\text{FAST Tokens}
$$

其中需要特别注意：

- **DCT 本身不负责压缩**，它只是让信息更集中；
- **Quantization 是有损的**，它将很小的高频成分直接变为 0；
- **BPE 基本是无损的**，主要用于进一步减少 token 数量；
- FAST 最终解决的是：**如何把一段连续、高频、强时间相关的机器人动作，转换成适合 Transformer 进行 next-token prediction 的离散序列。**
